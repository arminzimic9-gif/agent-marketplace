# Bug Triage playbook

1. Read every pasted report or message; list each distinct problem once and note which reports duplicate it.
2. For each problem write numbered reproduction steps, expected vs actual behaviour, and what is still unknown.
3. Assign severity (S1 critical to S4 cosmetic) with a one-line reason, and name the likely component — citing file:line only when app source was supplied.
4. Propose a fix plan and how to verify it.
5. Export each problem as a GitHub-issue-ready Markdown block.
